Transcrição de documentos trabalhistas

Um pipeline, dois extratores. Cartão de ponto e holerite compartilham envio, processamento, revisão e download.

0 de 0 tarefas

As cinco rotas

O contrato é literal. Um nome de campo diferente, um status escrito de outro jeito, e a avaliação automática não reconhece a resposta. Clique em cada rota para ver o formato exato.

POST/api/transcricoesrecebe o PDF

Recebe multipart/form-data com dois campos: arquivo (o PDF) e tipo, que só aceita cartao-ponto ou holerite — com hífen, sem acento.

Responde 202 imediatamente com o id, e o processamento continua por trás. Processar dentro do request quebra em produção quando o proxy da plataforma corta a conexão.

HTTP/1.1 202 Accepted

{ "id": "abc123" }
GET/api/transcricoes/:idconsulta o andamento

É por aqui que a tela descobre que o trabalho acabou. Enquanto status for processando, o campo value vem null. Em erro, o campo erro traz mensagem legível.

{
  "id": "abc123",
  "tipo": "cartao-ponto",
  "status": "concluido",
  "erro": null,
  "value": { "pages": [ ... ] }
}
PUT/api/transcricoes/:idsalva as correções

Recebe { "value": { ... } } com o que a pessoa corrigiu na tela e substitui a transcrição inteira. É o que faz a correção chegar na planilha.

GET/api/transcricoes/:id/planilhabaixa o resultado

Aceita ?formato=xlsx, csv ou json. Os três precisam funcionar — implementar só o xlsx está na lista de erros que já derrubaram entregas.

A planilha sai com as correções já aplicadas, não com a transcrição original.

GET/healthza aplicação está de pé?

Responde 200 quando a aplicação está viva. É o que a plataforma de deploy usa pra saber se o container subiu.

Regras que não se negocia

Estas valem para os dois tipos de documento e não dependem de qualidade de leitura. São erro de contrato, não de extração.

  • Nunca invente um valorCaractere que não deu para ler vira ?. A incerteza é por caractere, não por linha.
  • Nunca produza data impossívelDia 38 ou mês 13 é erro de leitura, não uma data.
  • Dinheiro é string, no formato brasileiro"2.389,77" — nunca 2389.77. Float perde o formato e introduz arredondamento.
  • Guarde o original e o interpretadodate_raw e time_raw preservam o que estava impresso; time_hhmm traz o normalizado.
  • Não ordene as linhasA saída segue a ordem do documento. Ordenar esconde justamente o sinal que a marcação de "não sequencial" existe para revelar.
  • Os avisos são derivadosBatidas ímpares, data não sequencial, página vazia e mês não sequencial saem do próprio dado na hora de exibir. Nenhum deles é campo no JSON.
  • fields e bases são coisas separadasBase INSS, Total Vencimentos e Valor Líquido não são verbas. Se entrarem em fields, viram colunas e contaminam a planilha inteira.
  • Nenhuma linha some em silêncioDia sem batida é punches: [], não ausência. Página de holerite sem dados continua na saída, marcada como vazia.

Cores da planilha

Especificadas literalmente no enunciado, e as mesmas na tela de revisão.

  • CabeçalhoNegrito branco sobre #173772.
  • Batidas ímpares, página vazia, ou ? na linhaPreenchimento #FFF3CD.
  • Data ou mês não sequencialPreenchimento #F8D7DA, com borda esquerda #DC3545 na primeira célula. Quando as duas valem, vermelho ganha.

Plano de trabalho

O esqueleto anda primeiro; a inteligência vem depois. O ciclo completo vale 20% e fica garantido cedo — se a semana apertar, ainda existe entrega válida. Marque conforme for concluindo.

Se estourar o tempo, corte profundidade de um tipo de documento — nunca o ciclo. Os dois tipos lidos parcialmente com o fluxo inteiro funcionando valem mais que um tipo perfeito sem interface e sem deploy. E escreva no SOLUCAO.md o que cortou e por quê: decidir o que sacrificar sob prazo é parte do que eles avaliam.

O que já derrubou entregas boas

Lista do próprio INSTRUCOES.md. Não é advertência genérica — é a régua de correção escrita em texto.

  • Duas aplicações em vez de umaOs dois tipos compartilham envio, fila, revisão, edição e download. Duplicar custa metade do tempo e aparece na nota de arquitetura.
  • Processar dentro do request HTTPFunciona local e quebra em produção. Pense em como o cliente descobre que o trabalho acabou.
  • Coordenadas fixasAmarrar a leitura a posições x/y quebra na primeira variação de layout, inclusive entre páginas do mesmo documento. Localize as colunas pelo cabeçalho.
  • Ajustar o código ao PDF de exemploUma data, um nome de coluna ou um número de páginas gravado no código resolve o exemplo e quebra em qualquer outro documento.
  • Assumir que todo PDF tem camada de textoDetecte e caia para OCR em vez de devolver transcrição em branco.
  • Aceitar qualquer coisa no uploadUm .txt renomeado para .pdf não vira transcrição. Recusar com 4xx é o ideal.
  • Implementar só o xlsxO contrato pede os três formatos, e os três precisam funcionar.
  • Deploy que não sobeTeste a URL numa janela anônima antes de mandar.

Como pontua

Precisão é a maior fatia sozinha, mas ciclo, arquitetura, segurança e documentação somam 55%. Volume de código, número de testes e tamanho do README não somam nada.

  • Precisão da extração30%
  • O ciclo completo funciona20%
  • Honestidade dos dados15%
  • Arquitetura e operação15%
  • Segurança e privacidade10%
  • Código e decisões10%
Honestidade dos dados é o critério que mais gente subestima. Um caractere marcado como ? custa muito menos que um caractere errado com cara de certo — o primeiro é visto e corrigido na revisão, o segundo chega ao cliente. Mas encher a saída de ? para se proteger também não funciona: quem diz que não leu nada, não transcreveu nada. O que eles querem ver é calibração.

Depois da entrega

Quem avançar faz uma sessão de ~40 minutos, ao vivo, estendendo a própria solução para um layout novo — com agente liberado. É por isso que entender o que você entregou vale mais do que entregar mais.
